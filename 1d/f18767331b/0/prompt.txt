# PR Creator Skill

## Purpose

Create well-formatted GitHub pull requests with:
- Conventional commit format for titles (feat:, fix:, docs:, etc.)
- Automatic issue linking with "Closes #issue" syntax
- PR template discovery and application
- Preview before creation

**Use when:** Completing features/bug fixes, opening draft PRs, linking issues, or ensuring PRs follow conventions.

---

## Prerequisites

- Changes committed to a feature branch (not default branch)
- GitHub authentication configured (MCP or gh CLI)
- At least one commit ahead of base branch

---

## Workflow

### 1. Verify GitHub Access

Check GitHub MCP tools availability, fall back to `gh` CLI if needed. If neither available, instruct user to authenticate.

### 2. Gather Repository Context

Auto-detect from git:
- Repository owner/name from `git remote`
- Current branch and base branch
- Commit count ahead of base
- Check for uncommitted changes (warn if present)

### 3. Check Branch Status

Verify branch is pushed to remote. If not pushed or has local commits, offer to push before creating PR.

### 4. Discover PR Template

Search for templates in standard locations:
- `.github/pull_request_template.md`
- `.github/PULL_REQUEST_TEMPLATE/*.md`
- `docs/pull_request_template.md`

If multiple templates exist, ask user to select one. See `references/pr-templates.md` for details.

### 5. Determine Conventional Commit Type

Analyze commit messages to suggest type (feat, fix, docs, etc.). Count type prefixes in commits. If no clear pattern, infer from file changes (.md → docs, test/ → test, etc.).

Present options to user with recommendation. See `references/conventional-commits.md` for type definitions.

### 6. Identify Linked Issues

Scan commits for issue references (#N) and closing keywords (Closes #N, Fixes #N). Prompt user to confirm which issues to link and whether to close them.

See `references/issue-linking.md` for GitHub linking syntax.

### 7. Generate PR Title and Description

Create title: `<type>(<scope>): <description>`
- Extract scope from branch name (e.g., `feature/auth-login` → `auth`)
- Use commit message for description
- Apply PR template if found
- Insert issue links in appropriate location

### 8. Preview PR Details

Display formatted preview showing:
- Repository, base, and head branches
- Full title and body
- Settings (draft status, maintainer can modify)

Allow user to edit title, body, toggle draft, or cancel.

### 9. Create Pull Request

Use GitHub MCP `create_pull_request` (preferred) or `gh pr create` (fallback). Handle common errors:
- Branch not pushed → push first
- PR already exists → show existing PR URL
- No commits ahead → cannot create PR

### 10. Report Results

Display:
- PR number and URL
- Status (ready for review / draft)
- Linked issues
- Commit and file count
- Suggest next steps (request reviewers, add labels)

---

## Options

### Draft PR
```bash
/pr-creator --draft
```
or respond "yes" when prompted during workflow.

### Custom Base Branch
```bash
/pr-creator --base develop
```

### Skip Template
```bash
/pr-creator --no-template
```

---

## Error Handling

| Error | Resolution |
|-------|------------|
| Not authenticated | Run `gh auth login` or configure GitHub MCP |
| Not in git repo | Navigate to repo or run `git init` |
| On default branch | Create feature branch: `git checkout -b feature/name` |
| No commits ahead | Make commits first |
| Branch not pushed | Accept prompt to push automatically |
| PR already exists | View existing PR, update if needed |
| Invalid title format | Must follow `type(scope): description` format |

---

## Output Format

```markdown
✅ Pull Request Created Successfully!

PR #15: feat(pr-creator): add conventional commit format for PRs
🔗 https://github.com/owner/repo/pull/15

Details:
- Status: Ready for review
- Base: main ← Head: feature/pr-creator
- Commits: 3 commits
- Files: 7 files changed (+250, -15)
- Linked Issues: Closes #13

Next Steps:
1. Request reviewers (optional)
2. Add labels (optional)
3. View PR: gh pr view 15 --web
```

## Notes

- **MCP-First:** Always prefer GitHub MCP tools over gh CLI
- **Title Enforcement:** PR titles must follow conventional commit format
- **Issue Linking:** Use "Closes #N" to auto-close issues on merge
- **Large PRs:** Warn if >20 files or >1000 lines changed
